# mTTD

*Torchlight: Infinite* 모바일 클라이언트의 파밍 수익을 실시간으로 집계하는 안드로이드 오버레이 앱.

게임을 수정하거나 메모리를 읽지 않는다. 게임이 스스로 남기는 로그 파일만 읽어 획득·소비 아이템을
추적하고, 시세를 곱해 수익을 계산한다.

## 무엇을 하나

- **회차별 수익 집계** — 맵 열기를 경계로 회차를 끊어 막대 그래프로 표시. 막대를 누르면
  그 회차에서 얻은 아이템 목록과 단가를 볼 수 있고, 잘못 잡힌 회차는 삭제할 수 있다.
- **게임 위 플로팅 HUD** — 경과 시간, 총 수익, 시간당 수익, 이번 맵 손익을 실시간으로.
  나침반·비콘 소비는 빨간 마이너스로 표시된다.
- **시세 두 곳 중 선택** — ETor(시즌 스냅샷, 전 아이템) / TTD(ttdiablo.com 한국 시세).
- **경매장 조회 반영** — 게임 안에서 시세를 조회하면 그 호가 평균이 스냅샷보다 우선 적용된다.

## 요구사항

| 항목 | 요구사항 |
|---|---|
| Android | 10 (API 29) 이상 |
| 게임 | `com.xd.TLglobal` · `com.xd.TLglobalTap` · `com.xindong.torchlight` |
| [Shizuku](https://shizuku.rikka.app/) | 필수. root 는 불필요 |

Android 11 부터 다른 앱의 `Android/data/` 는 일반 앱이 읽을 수 없다. Shizuku 가 shell(uid 2000)
권한으로 로그 파일을 대신 읽어준다.

## 설치와 사용법

### 1. Shizuku 준비

Shizuku가 이미 돌고 있다면 다음 단계로 넘어가면 된다.

1. Play 스토어 또는 [GitHub 릴리스](https://github.com/RikkaApps/Shizuku/releases)에서 Shizuku 설치
2. **개발자 옵션 → 무선 디버깅** 켜기
3. Shizuku 앱 → **무선 디버깅으로 시작** → 페어링 진행

> ⚠️ **재부팅하면 Shizuku가 꺼진다.** 부팅할 때마다 Shizuku 앱에서 다시 시작해야 하고,
> 그 전까지 트래커는 로그를 못 읽는다.

### 2. APK 설치

[GitHub Releases](https://github.com/listil/mttd/releases/latest) 에서 최신
`mttd-x.y.z-release.apk` 를 내려받아 기기로 복사한 뒤, 파일 관리자에서 실행 →
"출처를 알 수 없는 앱" 허용.

### 3. 최초 실행 설정

앱을 열면 **수익** 탭이 먼저 보인다. Shizuku 준비가 안 됐으면 안내 카드가 뜨는데,
**설정으로 이동** 버튼을 눌러 **설정** 탭으로 이동한다.

**Shizuku 연결** — **설정** 탭 상단의 **Shizuku 상태** 카드 네 항목이 모두 ✅ 여야 한다.

```
✅ 설치됨
✅ 바인더 살아있음
✅ 권한 허용            ← 버튼을 눌러 Shizuku 팝업에서 허용
✅ UserService 바인딩
```

권한을 허용하면 나머지는 자동으로 채워진다.

**오버레이 권한** — 같은 **설정** 탭의 **오버레이** 카드 → **권한 설정 열기** →
"다른 앱 위에 표시" 허용 → 앱으로 복귀.

여기까지 하면 나머지는 자동이다. 서비스가 게임 패키지를 찾고, 시세를 받고, 로그 폴링을 시작한다.
**앱을 껐다 켜거나 다시 방문할 필요 없다.** 화면 구석에 오버레이 아이콘(원형 배지)이 뜨면 준비된 것이다.

> 원형 배지가 안 보이면 — 같은 **오버레이** 카드에 **오버레이 표시** 버튼이 있다. 눌러서 수동으로
> 띄울 수 있다 (반대로 **숨기기** 로 다시 감출 수 있음). 권한을 나중에 허용했거나 배지를 실수로
> 닫았을 때 여기서 다시 켜면 된다.

### 4. 사용법

1. 게임 실행
2. 화면 구석의 **원형 배지**를 탭 → HUD 펼치기

   배지에는 위쪽에 경과 시간, 아래쪽에 시간당 수익(또는 픽업 전이면 픽업 개수)이 표시된다.

   | 배지 위쪽 | 상태 |
   |---|---|
   | `대기` (회색) | 아직 가방 정렬을 관측 못 함 |
   | `12:34` (초록) | 집계 중 |
   | `❚❚` (노랑) | 일시정지 |

   - **길게 눌러서 드래그** → 위치 이동 (짧게 누르면 HUD 토글)
3. HUD에 `🎒 게임에서 로그 오픈 후 가방 정렬을 눌러주세요` 가 뜨면 아래 두 가지가 필요하다:
   - **로그 오픈** — 게임 로그 파일에 인벤토리 관련 내용이 실제로 쌓이기 시작하는 것.
     [설정] -> [기타 설정] -> [로그 오픈]
     로그인 화면에 오래 머물러 있으면 이 문구가 계속 떠 있을 수 있다.
   - **가방 정렬** — 로그 오픈 이후, **게임 인벤토리에서 정렬 버튼**을 한 번 눌러야 한다.
     이때 게임이 가방 전체 스냅샷을 로그에 남기고, 그걸 기준으로 이후 획득/소비량을 계산한다
     (마을 귀환이나 재접속으로도 같은 스냅샷이 발생한다).
4. 이후 파밍하면 자동 집계

**HUD 항목**

| 표시 | 의미 |
|---|---|
| 경과 | 가방 정렬 관측 시점부터의 시간 (일시정지 구간 제외) |
| 총 수익 | 획득(+) − 소비(−) 누적 시장가, 괄호 안은 경매장 세금(1/8) 반영한 실수령 예상치. 단위는 최초의 불꽃 결정 |
| 시간당 | 총 수익 ÷ 경과 시간 (마찬가지로 괄호 안이 실수령 기준) |
| 맵 진입 | 진입한 맵 수 |
| 이번 맵 | 현재 런의 아이템별 누적. 맵 열 때 초기화되며, 나침반·비콘 소비가 **빨간 마이너스**로 먼저 찍힌다 |

**버튼**

| 아이콘 | 동작 |
|---|---|
| ⚙️ | 앱 설정 화면 열기 |
| ⏸ / ▶ | 일시정지 · 재개 (경과 시간과 집계 모두 멈춤) |
| 🔄 | 세션 리셋 (수익·시간 초기화, 가방 정렬을 다시 눌러야 함) |
| ✕ | HUD 접기 (아이콘만 남음) |

## 개인정보 / 보안

- **아웃바운드 요청은 시세 API·업데이트 확인·아이템 아이콘 CDN·(유저가 직접 누를 때만) 캐릭터
  빌드 내보내기 뿐**이다. 그 외엔 계정·아이템·플레이 데이터를 어디로도 보내지 않는다.
  - `etor-zero.981001.xyz` — 시즌 시세 (시즌 ID 만 전송)
  - `ttdiablo.com` — 한국 시세 (정적 JSON)
  - `api.github.com` — 앱 시작 시 1 회, 새 버전 확인
  - `cdn.tlidb.com` — 아이템 아이콘 이미지. 앱에 내장하지 않고 필요할 때마다 불러온다
    (오프라인일 땐 아이콘만 안 보이고 집계 자체는 그대로 동작)
  - `mini-tlidb.winterer.workers.dev` — 설정 화면의 "캐릭터 장비 내보내기" 버튼을 **직접 눌렀을
    때만** 전송. 로그인 시 게임이 내려주는 캐릭터 전체 스냅샷(장비/스킬/석판/천명/핵심 재능/
    프리즘/히어로 추억)을 그대로 올리고, 서버는 1회용 열람 URL을 돌려준다(10 분 미사용 시 자동
    폐기). 자동으로는 절대 전송되지 않는다.
- Shizuku 로 실행되는 `UserService` 는 **읽기 전용**이다. 파일 생성·수정·삭제 op 가 없고,
  경로는 게임 데이터 디렉토리로 화이트리스트되어 있다.
- 위치·카메라·마이크·전화 상태·광고 ID 권한은 **선언 자체를 하지 않는다**.
- 집계 결과는 기기 안에만 있다.

## 업데이트

앱 시작 시 GitHub Releases 를 1 회 조회해 새 버전이 있으면 배너로 알린다. **설치는 하지 않는다** —
자동 설치를 하려면 `UserService` 에 APK 설치 능력을 줘야 하는데, 읽기 전용 원칙을 지키기 위해
그 경로는 열지 않았다. 자동 업데이트를 원하면 [Obtainium](https://github.com/ImranR98/Obtainium)
같은 도구에 이 저장소를 등록하면 된다.
